## 状态用词

- **待处理／进行中：**尚未交付；进行中必须有实际工作。
- **本地已实现：**代码或数据已具备能力，验证可仍待完成。
- **待验收：**列明缺少的设备、场景或结果，不笼统写“已完成”。
- **验证通过：**写明日期、对象和验证范围。
- **已上线：**有目标提交、前后端部署及线上抽查证据后才能使用。

## 2026-09-21 微信图鉴：工具内闭环验证与阻塞缺陷修复（第四轮）

**修掉的阻塞缺陷：**

1. **`app.wxss` 的 `*` 通配选择器 → 全站白屏。** 用开发者工具自带的 WXSS 编译器 `wcsc` 本机编译，得到唯一报错 `app.wxss(1:3277): unexpected token '*'`。实测 WXSS **不支持任何形式的通配选择器**，且 `wcsc` 遇到即让整个文件失败。受影响的是两处「减少动态效果」规则（`.reduced *{…}` 与 `@media(prefers-reduced-motion:reduce){*{…}}`），改为逐个列出实际带动的类。
2. **`document-blocks` 的 `<text user-select wx:for>` 破坏行内流。** 用最小复现工程做同页对照确证：`user-select` 与 `wx:for` 同处一棵子树时，`<text>` 被提升为块级，项目符号独占一行、「加粗+正文」混排段落被逐行拆开。规则正文 205 个块里 101 个受影响，去掉 `user-select` 后恢复（项目无「可选中／长按复制」要求）。
3. **WXML 不解码 HTML 实体。** `wcc` 实测 `&amp;` 编译成字面量，规则页页眉一直显示 `LEARN &amp; EXPLORE`，改为直接写 `&`。

**防回归：** 把工具自带的 `wcc`/`wcsc` 接进 `mini:test`（第 21 项，装了工具才跑，CI 无 IDE 则 `[skip]`），另加两条纯静态兜底（禁用 `*` 选择器、禁止 `<text user-select wx:for>`）。三条防线均以人为注入反向验证过能准确报错并给出原始位置。
