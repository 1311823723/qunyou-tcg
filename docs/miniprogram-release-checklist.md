## ⚠️ 微信认证：我说错过，这里是更正（2026-09-22）

本清单早期版本写过一句「个人主体不做微信认证也能正常发布，未认证只影响支付、卡券、手机号获取」，并且说「个人主体本身不支持认证」。**这两句都不成立，是我没查实就写下的**，而账号持有者已经据此交了 30 元认证费。更正如下：

**个人主体可以做微信认证，官方价 30 元／次**（微信开放社区官方答复口径：企业主体 300 元、个人主体 30 元、个体工商户 30 元优惠价）。所以这 30 元不是被谁坑了，是微信的标准价。

真正该问的问题不是「不认证能不能上架」，而是「不认证能不能被人找到」。查下来的官方口径是：

| 来源 | 原文要点 |
| --- | --- |
| 微信开放社区官方答复（精选） | 个人小程序未认证**可以正常使用基础功能**，「基础开发、发布上架、API 调用等基础功能不受影响」；但受限的包括：无法开通微信支付、**无法通过名称搜索找到小程序（需完成认证才能开启被搜索能力）**、无法获得高级接口权限 |
| 微信官方文档《快速创建个人小程序》 | 自 2023-12-25 起新注册账号默认未认证，**需完成认证后方可获得「被搜索、分享」能力，未认证不影响账号发布上架** |
| 实际后台站内通知（他人公开记录，2026-06-27） | 「账号未完成微信认证……请在 X 日前完成微信认证，**逾期未完成认证将影响账号『被搜索』能力**」 |

**结论：未认证不影响上架，但会影响「被搜索」和「分享」。** 对这个项目来说这是致命的——它是一个给群友用的图鉴查询工具，别人主要靠**在微信里搜名字**找到它。搜不到，就只能靠扫码和链接转发。

所以：**这 30 元不要退、也不要取消，让它走完。** 已缴费属于审核服务费，官方口径是无论成功与否通常不退还；更重要的是认证状态本身对本项目是有用的，不是沉没成本。

顺带两条连带影响，都指向同一件事——**先把小程序名称定死**：

- 认证费按「次」计，改小程序名称或主体名称都要重新认证、重新交费。
- 备案中与备案通过后也都不允许改名改主体（见第一节第 2 条）。

> 本次更正也提醒：涉及「能不能上线、要不要花钱」这类结论，不能凭一般印象写进清单。凡写进本文档的平台规则，我应当注明官方来源，不能确定的要标「待核实」而不是写成断言。

### 2. 小程序备案（唯一真正的时间卡点，而且是上传的前置条件）

2023-09-01 起强制。注意它不只是「发布前」要做——**只有微信侧备案状态显示「已完成」，开发者才能正常上传代码、提交审核、更新版本**。所以备案必须先启动，否则连体验版都传不上去。

路径：后台首页或 设置 → 基本设置 → 小程序备案 → 去备案。

- 个人主体材料最简：**本人身份证正反面 + 实名手机号 + 应急联系人**（注意：应急联系人的手机号**不能与本人同一号码**），提交后需**本人人脸核验**。不需要营业执照，也不需要先做微信认证。
- 周期：平台初审 1–2 个工作日 → **工信部 12381 短信核验（24 小时内有效，超时作废重报）** → 通信管理局 7–20 个工作日。整体常见 1–2 周。
- **备案前先定死小程序名称**：备案中与备案通过后都不允许改名改主体。名称不得含企业／单位名义，不得涉及新闻、金融、医疗、教育、网约车等前置审批领域。
- 备案通过后要在小程序内展示备案号（见第三节第 2 条）。

**为什么这样写**——三条口径，改字时请一并保持：

1. **只写真实有的功能**，不写「即将上线」「规划中」。描述与小程序实际页面一一对应：检索、卡面文字、效果、形态、预组构成、入门、完整规则、关键词释义、本机收藏。这几项都能在开发者工具里点出来。
2. **刻意避开会触发前置审批或类目错判的词**：全文不出现「游戏」「网络游戏」「攻略」「竞技平台」「商城」「交易平台」「社交」「UGC」「直播」「金融」「教育」「医疗」「新闻」。所以写的是「卡牌爱好者」而不是「某游戏玩家」。**本项目自有的另一个站点里确实有「在线对战大厅」，但那是网站、不在小程序内**，小程序侧 `OFFICIAL_WEBSITE_EMBED_ENABLED` 永久为 `false`，不会内嵌也不会跳转，因此备注里不描述、也不声明与之相关的能力。
3. **主动写成「不做什么」而不是留白**：个人主体不能选经营类目、也不能涉及前置审批领域，「不提供联网对局／无账号登录／不收集个人信息／不涉及销售充值支付／无用户发布内容／不投放广告／完全免费」这一段是给审核员的自证，比只写「是查询工具」通过率高得多。这七条也都与 `pages/about` 页的实际声明一致，不冲突。

写完后建议把最终采用的那一档抄进本文件（或用 git 记下来），并在[交接文档](miniprogram-handoff.md)里留一句，方便以后对齐。

### 4. 用户隐私保护指引 · 剪贴板（阻断，且本地测不出来）

项目用了 `wx.setClipboardData` 两处：`detail` 页「复制文字」、`website` 页「复制网址」。

必须在后台声明：设置 → 基本设置 → 服务内容声明 → 用户隐私保护指引 → 增加信息类型 → **剪贴板** → 填写用途 → 生成协议。

**为什么现在看不出问题：** 小程序在**未声明**的情况下，复制接口的行为与账号状态有关——本地调试时正常，一旦以正式身份提交并在真机运行，未声明就会直接返回
`{errMsg: "setClipboardData:fail api scope is not declared in the privacy agreement", errno: 112}`。
这是「本地能跑 ≠ 线上能跑」的典型，**必须在真机上实测一次复制**，不要凭本地表现判断。

若声明后仍失败，再考虑在 `app.json` 加 `"__usePrivacyCheck__": true` 并用 `wx.onNeedPrivacyAuthorization` / `wx.requirePrivacyAuthorize` 处理授权弹窗——**先实测再决定，不要凭猜改**。

7. **⚠ 类目风险：别让审核把它当成「游戏」。** 个人主体不能选游戏类目下的「牌类」二级类目（小游戏通道还涉及版号与适龄提示），一旦被判定为游戏类内容就会卡住。本项目**没有可玩内容**，只有查询、阅读与收藏，属于工具类；但界面上有几处措辞容易引起误读：
   - `pages/rules` 的标题是「对战指南」；
   - `content/presentation.json` 的六步入门里有「这是一场 1 对 1 的卡牌对战」「游戏简介」「游戏组件」。

   这些是**面向玩家的正式语料，我没有擅自改**。建议在提审前评估是否把上述表述收窄为「规则指南」「规则简介」「组成」之类，并在小程序名称、简介、提审截图中始终强调「查询工具」。改不改由你定，改的话我按你的口径执行并复跑 `mini:test`。

## 四、上线路径

```
定死小程序名称 → 提交小程序备案（最长的一段，先启动）
                        ↓（备案期间并行推进）
   定图源方案 → 配 downloadFile 合法域名 → 配隐私保护指引（剪贴板）
                        ↓
   补备案号展示入口 → 真机全流程验收（第二节 8 项）
                        ↓
   上传代码（版本号 + 备注）→ 体验版验收 → 提交审核 → 审核通过 → 发布
```

注意顺序：**备案没通过之前上传不了代码**，所以「配域名、配隐私指引、真机自测、补备案号入口」这几件要在备案等待期内做完，备案一通过就能直接上传。

上传与发布命令（**需要你的明确授权才执行**）：

```bash
CLI=~/Applications/wechatwebdevtools.app/Contents/MacOS/cli
"$CLI" upload --project "$PWD/miniprogram" -v 1.0.0 -d "首次上线：卡牌图鉴、预组、指南"
```

`upload` 需要已登录且为管理员／开发者，产物是「开发版本」，之后仍要在后台手动提交审核与发布。
