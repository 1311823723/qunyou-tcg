# 决策记录

记录日期：**2026-09-06**。以下整理自已确认需求与现有项目约定，不新增游戏规则。具体实现要求仍见对应专题文档。

## DEC-001：正式数据与规则优先

**状态：沿用。** 卡牌效果与费用来自正式 JSON；UI 不解析中文效果另写规则。规则不清时记录建议，不能用当前实现反向定义规则。

原因：避免卡面、服务端和客户端出现三套不同效果。依据：[开发约定](../AGENTS.md)、[产品规格](auto-battle-product.md)的规则优先级。

## DEC-002：保留现有结算引擎，统一输入流程

**状态：已确认。** 当前体验改版沿用服务端权威状态与合法行为；两端共享来源、选择、确认、等待结算流程。返回只回退本地步骤，不撤销已支付费用或已观看结果。快捷出牌默认关闭，技能费用、转化、响应、濒死和阶段结束保留明确确认。

原因：改善操作体验，同时保持结算顺序与隐藏信息边界。依据：[统一交互契约](auto-battle-product.md)、[技能引擎](auto-battle-skill-engine.md)。

## DEC-003：敌我清晰，但保留原有图标和动画

**状态：已确认；图标保留是用户对上一版改动的明确修正。** 固定敌上我下，身份用文字及颜色共同区分；当前回合与当前决策者分开。体力水晶、Mega 水晶、Z 水晶及受伤／回复、进度增长、就绪和形态动画必须保留，不以隐藏图标、仅显示数字作为“简化 UI”的默认手段。

竖屏按实际内容安排本体／状态与角色区域，把空间用于可读卡牌和可操作手牌，不让空阵地均分剩余高度。动效不得遮挡或吞掉输入；遵循减少动态效果偏好。参考同类游戏的布局原则，保留本项目的资产与玩法。

原因：上一轮虽然强化了敌我辨识，却隐藏了用户已有资产并产生大块留白，未满足实际体验要求。维护入口：[界面风格](style-guide.md)、[产品规格](auto-battle-product.md)。

## DEC-004：实现、验证和上线分别记录

**状态：采用。** 本地测试不等于真机验收，截图检查不等于真人体验，构建成功不等于已经部署。状态必须附范围与证据；未核验就写未核验。

原因：避免多人或后续 AI 接手时误判进度。维护入口：[项目状态](project-status.md)、[发布清单](release-checklist.md)。不改变“仅在用户明确要求时提交／推送”的既有约定。

## 变更方式

新决定记录日期、状态、选择、理由及影响文档。改变旧决定时注明由哪个新记录取代，保留原理由；不要静默覆盖，也不要将讨论中的选项标成已确认。

## DEC-006：流派名优先表达核心操作

2026-09-08：预组组名继续承担称号和世界观功能，流派名则优先让玩家一眼看出主要操作。南山五采用「破魔组／反制流」，KGY采用「巡界组／骑士流」；前者突出等待技能后反击，后者直接提示六种骑士卡。技术 ID 不随名称变化。

影响：预组页面和攻略必须同时展示组名、流派关键词和一句玩法说明；流派目录中的 `name` 继续作为正式玩家可见名称，技术 ID 不随命名讨论变化。

交叉组沿用「交叉组／交叉流」，因为其核心不是单一定位，而是有意识地交替使用角色技能与【出刀】。

## DEC-005：说明来自规则执行点，默认简短显示

2026-09-08：保留现有界面资产与交互，使用可选服务端描述。合法性与阻塞提示共用只读遍历，专属说明随技能模块提供；直接原因显式穿过可序列化上下文。公开描述仅白名单字段，缺少证据时展示结果或通用提示。费用预览只覆盖当前提交，后续选择不提前执行。细分覆盖见[说明记录](auto-battle-explanations.md)。
