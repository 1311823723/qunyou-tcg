# 宝旅团微信图鉴 · 产品规格

2026-09-21。用户已确认“沉浸式卡牌图鉴”，本规格取代基础搭建时的三入口默认方案。

## 定位与边界

新玩家从本体原画认识玩法，进入预组、角色与图文入门；老玩家直接搜索完整效果，收藏常查卡。收藏表示感兴趣或常查，不代表拥有实体卡，仅存本机。无登录、对战、自由组牌、账号同步、抽卡、交易、排行、胜率或交互式教学。

## 信息架构

底部四入口：首页、卡牌、预组、规则。卡牌分类列表、单卡、预组详情、最近浏览、官网是栈内页面。

- **首页（启动台）**：品牌区、一句玩法说明、全量搜索入口，以及「规则 / 卡牌 / 预组」三个分类入口按钮。按钮用 01／02／03 序号、强调色与真实数量（规则 3 节、卡牌 152 张、预组 12 套）表达层级，数量全部由数据计算。有记录时才显示收藏与最近浏览。
- **图鉴（卡牌）**：本体牌 12 / 角色牌 120 / 手牌 20 三个分类入口，另给全量搜索。分类进入独立列表页，竖屏双列完整卡面；搜索名称、ID、标签、技能与效果，多词同时匹配；手牌可再按基础牌／行动牌／骑士卡子筛选，角色可按定位、预组组合筛选（默认收起）。归属由预组引用计算，支持跨预组复用。「全部／已收藏」切换，显示条件及清空入口。返回沿用页面实例和查询条件；实际原生滚动恢复待验。
- **预组**：承接原首页内容——手动滑动本体主视觉、新手图文入口、全部 12 套预组网格，以及收藏与最近浏览。精选顺序（上头组、操作组、执棋组）由展示配置引用正式 ID。
- 单卡：完整卡图与高清预览、收藏、归属标签、正式费用／时机／技能、相关预组和分享。正背面配套文字同步；Z 背面仍显示原特性，Mega／极巨化背面显示各自效果。手牌用花色点数 picker。骑士卡明确提示暂无正式成卡图，呈现普通和 FINAL 正式文字。非法 ID、缺图及图片加载失败均能继续导航和查文。
- 预组：原画列表进入独立详情，展示本体、玩法简介、核心操作和完整 16 张角色卡册；简介独立维护，不在页面复制技能效果。
- 指南：六步图文入门、完整正式规则的目录与章节返回、关键词搜索。规则转换为原生段落、强调、列表和表格内容；不执行 HTML 或加载远程规则。
- 本机记录：稳定 ID；最近浏览去重且上限 30；失效 ID 清理；存储失败提示，当前会话仍可浏览和收藏，但不承诺该次记录持久化。

## 视觉与反馈

深墨蓝／炭黑底，暖白正文、低饱和金色标题、青色选中反馈；已有原画为视觉主体，薄边框、完整卡面、小胶囊标签。规则正文 16px、1.8 行高，主要按钮至少 44px。竖屏双列，宽屏适当增加列数；安全区留白，长文正常滚动和选择。

2026-09-21 视觉升级（回应「太普通」）：页面底色改为深靛蓝到近黑的多层径向渐变，标题区加金色细线与菱形节点收束；分类入口是带左侧强调竖条、超大序号、右上角真实数量与「进入 →」的圆角卡，强调色按分类区分（规则青、卡牌金、预组紫）。仍遵守 [风格指引](style-guide.md)：暗色桌面、TCG 卡牌感、轻微霓虹，**不引入**高饱和渐变、发光描边堆叠、emoji 或廉价页游风。

分类卡用 `<view role="button" hover-class="pressed">` 而不是 `<button>` 承载：微信 `button` 自带默认内边距与 `::after` 边框，做卡形容器时样式互相干扰；需要点击的整块卡片统一走 view + `role` + `hover-class`。

卡面加载态：远程卡面首次加载要数秒，期间不能只是一块空白。`card-tile` 在 `bindload` 之前显示「卡名 + 卡面载入中…」占位层（轻微脉冲，`prefers-reduced-motion: reduce` 时静止），加载成功让开，失败走「图片暂不可用 · 点击读文字 + 重试图片」。文字永远可读，任何状态下都不隐藏卡牌。

首页不自动轮播。点击立即反馈；页面轻淡入约 160ms，切面约 200ms，连续操作不被动画锁住。无音乐或粒子。样式响应减少动态效果媒体查询，指南另提供本机静态模式开关；系统设置在微信内的实际映射仍需真机验证。

## 内容核对与待确认

入门的每步在 `miniprogram/content/presentation.json` 记录正式规则章节引用，构建校验引用存在。已人工按游戏简介、游戏组件、区域、开局、回合、出牌响应、布阵、费用结算、休整、退场、濒死逐项核对。

已知历史冲突：`docs/keywords.md` 的“本体”写体力降至 0 即失败，同文件“濒死”及 `docs/rules.md` 允许救援。小程序保留正式全文，不自行裁定或修改；入门按完整濒死流程概述。请规则负责人在正式源中确认并统一。重复的判定／拼点章节保留，目录锚点唯一；未合并条文。钛晶化在正式规则中仍标未来待定，不包装成已实现玩法。

## 验收标准

首页→预组→角色；组合搜索和收藏筛选；返回条件／位置；正背面及文字；手牌 picker／高清；重启收藏／去重与失效清理；规则目录／关键词；缺图、弱网、离线文字；微信分享直达后继续浏览。覆盖 320、390、430px 竖屏和横屏、安全区及大字号。

代码检查、浏览器近似布局、微信开发者工具、iOS、安卓、首次玩家体验分别记录。[验收记录](miniprogram-verification.md)是实际状态依据，不能用代码完成推断用户体验已验证。


## 首页官网入口补充

首页标题旁新增“官网 ↗”，进入独立 website 页。固定官网地址来自项目 README：`https://qunyou-tcg.pages.dev`，在 `src/config.ts` 单独维护，不随卡图域名变化。当前 `OFFICIAL_WEBSITE_EMBED_ENABLED=false`，展示可选中网址与明确的复制按钮；不自动操作剪贴板，不声称已打开浏览器。已实现 web-view 路径及加载失败回退，但必须核验真实账号 web-view 能力、当前微信官方要求及业务域名后才启用，不能仅在工具里关闭校验。页面不接受任意外部 URL 参数。

官网原生打开／复制、返回保留图鉴状态仍待微信与真机验证。Node 测试增至 19 项且通过，小程序类型检查通过，包体约 1077 KiB。未提交、推送或发布。

2026-09-21 核验结论：web-view 依赖「业务域名」，而业务域名**不开放给个人主体账号**，且要求域名已 ICP 备案并放置微信校验文件；`pages.dev` 域名无法备案。因此在当前条件下内嵌访问不可用，`OFFICIAL_WEBSITE_EMBED_ENABLED` 保持 `false`，继续提供可选中网址与复制按钮。若将来具备非个人主体与已备案自有域名，再按业务域名流程验证后开启。详见[验收记录](miniprogram-verification.md)。

## 2026-09-22 已确认视觉修订

- 图鉴 tab 直接显示卡面，搜索与牌种切换常用可见，定位和预组筛选折叠；保留旧 collection 深链。共用手牌仅基础牌、行动牌，骑士卡为独立牌种。
- 正文使用安静暗底和完整效果，预组页保留原画色彩。底栏：首页／图鉴／预组／指南。网站按钮继续遵循原有主体／业务域名限制与复制网址回退。
- 不把本地视觉实现称为已上线或真机体验已验证。
