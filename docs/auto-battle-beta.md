# 自动对战 Beta

自动对战 Beta 与经典手动对战共用大厅、昵称、房间码、重连和观战入口，但使用独立的牌桌页面与 Durable Object。自动版出现问题时，不会改变经典房的状态或操作方式。

彻底自动结算的产品目标、发布门槛和阶段见 [`auto-battle-product.md`](auto-battle-product.md)；技能注册、事件、可持久化选择与测试规范见 [`auto-battle-skill-engine.md`](auto-battle-skill-engine.md)。

## 当前自动范围

- 自动开局：双方摸 5 张手牌、暗置上阵 2 张角色，并随机决定先手。
- 六阶段循环：准备、摸牌、出牌、布阵、弃牌、结束。
- 摸牌阶段自动摸 2 张；布阵阶段至多上阵 2 张角色，角色区最多 4 张。
- 弃牌阶段按 `min(当前体力, 4) + min(己方明置角色数, 2)` 自动检查上限。
- 54 张实体手牌的目标、响应、牌区移动、伤害、回复与阶段效果。
- 响应栈、【闪避】、【别急】、【紧急会议】、小王转化和濒死【急救】。
- 牌堆不足时将共用弃牌区洗回牌堆。
- 胜负判断、公开日志、断线重连和观战隐私。
- 10 张本体的正面特性、Mega、Z 招式，以及 Joker 与 KGY 的极巨化：系统自动记录进度、翻面、次数、骑士卡、能量、极巨体力和费用修正。
- 全部 120 张角色（预组引用去重 117 张、非预组 3 张）已接入触发、费用、目标与分支的全自动结算。

自动版不设置倒计时。存在响应、选择、濒死或未完成结算时，当前玩家不能推进阶段。

## 本体技能自动结算

十个流派本体已使用结构化事件自动结算，不从卡面中文临时解析效果。自动范围包括：

- 爆杀流的伤害进度、额外【出刀】次数和 Mega 结束阶段【出刀】。
- 密裁的有效观看计数、展示手牌、选择弃置和 Mega 摸牌。
- 行动流的行动牌计数、伤害检查和 Mega 牌堆顶选牌。
- 拟态流的虚拟牌触发、暗置补位、结束阶段休整和 Mega 费用减免。
- 调度流的明置计数、牌堆顶整理、对手明置换牌和 Z 招式换阵。
- 卖血流的受伤判定、红黑分支、随机弃牌和 Z 招式弃牌区回收。
- 伏击流的离场补位，以及 Z 招式对退场伏击角色的限时免费发动。
- 防御流的抵消/防止/减伤计数、摸牌观看，以及 Z 招式致命伤害防止。
- 连携流的本回合定位记录、摸牌/换手选择、极巨化入场窗口、精准换手和独立极巨体力。
- 巡界流的骑士卡获取、同定位角色费用、六种普通/FINAL效果、极巨化转换和独立极巨体力。

需要玩家发动的可选本体技能会进入私有选择窗口；对手和观战者只会看到等待状态和最终公开结果。

10 张本体均已迁移为 `worker/src/skills/bodies/` 下的独立技能模块。正面被动、Mega 强化、主动 Z 招式、防御 Z 招式的致伤拦截，以及 Joker 与 KGY 的极巨化都由同一注册架构调度。

## 角色技能与预组解锁

角色技能不从中文效果文本推断规则。`data/cards/character_automation.json` 为 120 张角色登记机器可读的触发时机、次数限制和可用原子操作；技能费用仍读取角色牌 JSON 中的结构化 `cost`。

系统负责验证时机、明置发动者、支付休整或退场费用、处理休整摸牌、记录次数并写入公开日志。已解锁预组使用稳定 ID 的独立角色模块，多步选择保存为 `SkillContinuation`，断线后可从同一步骤继续。

新建自动房可选择全部 10 套已解锁预组，或使用共享自选编辑器，从 10 张已开放本体和全部 120 张角色中选择 16 张不重复角色。Joker 与 KGY 均已有对应预组和自动本体模块；南山五与花生壳尚未实现。服务端对创建、加入、换组和准备均校验，不能绕过前端限制。经典模式不受影响。完整进度见 [`auto-battle-character-status.md`](auto-battle-character-status.md)。修改角色时机或费用后运行：

```bash
npm run automation:sync
npm run validate
```

辅助结算层保留用于旧房间兼容。自动模式的自选草稿和当前牌组分别保存为 `qunyou-auto-custom-deck-v1` 与 `qunyou-auto-loadout-v1`，不覆盖经典模式草稿；首次打开编辑器可复用符合自动模式限制的经典草稿。非法或过期草稿回退到已解锁预组。

## 接口与部署

- 经典房：`/rooms/**`，页面 `/play/room`。
- 自动房：`/auto/rooms/**`，页面 `/play/auto/room`。
- 大厅摘要以 `mode: "classic" | "auto"` 区分模式；旧摘要缺少该字段时按经典房处理。
- 自动房由 `AutoBattleRoom` 保存，Cloudflare 迁移版本为 `v3`。

## 状态同步与性能诊断

- Worker 是唯一权威状态：客户端只提交操作意图，操作成功持久化后才发送确认和新快照。
- 对局继续使用按观看者脱敏的完整快照，不依赖客户端增量状态推测，以保证断线重连和隐藏信息一致。
- 普通出牌、响应、技能和阶段操作只保存房间；只有开局、玩家连接变化、观战人数变化和房间结束才同步大厅摘要。
- 客户端同一时间只发送一项权威操作；超过 300ms 显示处理状态，超过 2 秒提示网络较慢，不自动重发。
- 在自动房页面 URL 添加 `perf=1` 可打开开发诊断面板，查看往返、规则处理、持久化、浏览器重绘、快照大小和更新区域。普通玩家默认不显示该面板。

部署时先发布 Worker，再发布前端。完整本地检查：

```bash
npm run validate
npm run typecheck
npm run test:battle
npm run build:battle
npm run test:battle:auto:live
npm run test:battle:e2e
npm run build:web
```

## 牌桌操作与手机适配（2026-09-05）

- 手机及宽度不超过 1024px 的窗口使用紧凑牌桌，随窗口横竖比例自动排布；不再保存可能与当前屏幕方向冲突的布局，也不整体缩小手机操作区。
- 竖屏将操作区放在己方角色与手牌之间，手牌横向滑动；矮屏允许牌桌纵向滚动，保留文字和按钮尺寸。全屏为可选操作，浏览器不支持时仍可旋转设备切换布局。
- 出牌按钮明确显示“结束出牌”；布阵由玩家选择上阵、明置或“完成布阵”，不再自动上阵或自动离开布阵阶段。无决策的准备、摸牌、弃牌、结束阶段仍可自动推进。
- 无关的在线状态刷新不会清空同一选择窗口的选牌；刷新卡牌区域时保留滚动位置和键盘焦点。弃牌显示已选数量，不能使用的响应牌点开详情。
- 操作确认与快照兼容两种到达顺序；等待期间的慢网络提示独立于自动推进计时器。此轮不改变正式卡牌效果、规则或服务端存档格式。

## 统一操作流程与电脑快捷出牌

- 电脑与手机共用提交前草稿：选牌后直接选择必要目标或转化分支；技能、本体、骑士卡和拆弹先显示费用及选择，再确认提交。电脑操作区固定在手牌上方，日志和手牌独立滚动，不整体缩放牌桌。
- “上一步”只回退本地选择并保留来源；“取消操作”退出草稿。服务器已开始的结算不能撤销，响应中的“取消”仅取消选牌，“放弃响应”仍是独立的规则操作。选响应牌后仍展示发起者与原效果。
- 电脑左键选牌，Enter 确认当前完整选择，Esc 或牌桌内右键返回。输入框、文字选区、链接及已打开的原生弹窗不拦截快捷键；按住 Enter、等待服务器或消息更新不能重复提交。
- 顶栏“快捷出牌”默认关闭，偏好保存在 `qunyou-auto-quick-play-v1`。开启后，服务器明确允许且只有一个完整普通出牌意图时可双击；指定角色目标的手牌可拖到合法目标提交。技能费用、转化、响应、濒死及阶段结束不使用快捷提交。触控设备不启用双击出牌。
- 整理牌序改为牌顶／牌底双区域。电脑可拖动，手机和键盘用户可通过“放到牌顶／牌底”和前后移动按钮操作；确认时才向服务器提交顺序。
- 服务端增量提供交互描述与己方不可用原因，客户端不解析中文技能费用。费用描述应用现有减免及同等费用上下文，但不消耗修正；结算中触发的其他技能仍可能依法改变最终支付。
- 发布顺序仍为 Worker → 前端。没有新增命令或存档迁移；缺少快捷资格描述的旧快照不会启用快捷提交。

验收分别记录：本地 Chromium 真双人流程、受控消息的费用/目标/快捷输入/网络回归，以及尚需实际设备完成的 iOS Safari、安卓触控与系统全屏验收。浏览器模拟不替代真机结论。
