# 自动对战 Beta

自动对战 Beta 与经典手动对战共用大厅、昵称、房间码、重连和观战入口，但使用独立的牌桌页面与 Durable Object。自动版出现问题时，不会改变经典房的状态或操作方式。

彻底自动结算的产品目标、发布门槛和阶段见 [`auto-battle-product.md`](auto-battle-product.md)；技能注册、事件、可持久化选择与测试规范见 [`auto-battle-skill-engine.md`](auto-battle-skill-engine.md)。

## 当前自动范围

- 自动开局：双方摸 5 张手牌、暗置上阵 2 张角色，并随机决定先手。
- 六阶段循环：准备、摸牌、出牌、布阵、弃牌、结束。
- 摸牌阶段自动摸 2 张；布阵阶段至多上阵 2 张角色，角色区最多 4 张。
- 弃牌阶段按 `min(当前体力, 4) + min(己方明置角色数, 2)` 自动检查上限。
- 54 张实体手牌的目标、响应、牌区移动、伤害、回复与阶段效果。
- 响应栈、【闪避】、【别急】、【紧急会议】、小王转化和濒死【急救】。
- 牌堆不足时将共用弃牌区洗回牌堆。
- 胜负判断、公开日志、断线重连和观战隐私。
- 9 张本体的正面特性、Mega、Z 招式与 Joker 极巨化：系统自动记录进度、翻面、次数、能量、极巨体力和费用修正。
- 全部 120 张角色（预组引用去重 106 张、非预组 14 张）已接入触发、费用、目标与分支的全自动结算。

自动版不设置倒计时。存在响应、选择、濒死或未完成结算时，当前玩家不能推进阶段。

## 本体技能自动结算

九个流派本体已使用结构化事件自动结算，不从卡面中文临时解析效果。自动范围包括：

- 爆杀流的伤害进度、额外【出刀】次数和 Mega 结束阶段【出刀】。
- 密裁的有效观看计数、展示手牌、选择弃置和 Mega 摸牌。
- 行动流的行动牌计数、伤害检查和 Mega 牌堆顶选牌。
- 拟态流的虚拟牌触发、暗置补位、结束阶段休整和 Mega 费用减免。
- 调度流的明置计数、牌堆顶整理、对手明置换牌和 Z 招式换阵。
- 卖血流的受伤判定、红黑分支、随机弃牌和 Z 招式弃牌区回收。
- 伏击流的离场补位，以及 Z 招式对退场伏击角色的限时免费发动。
- 防御流的抵消/防止/减伤计数、摸牌观看，以及 Z 招式致命伤害防止。
- 连携流的本回合定位记录、摸牌/换手选择、极巨化入场窗口、精准换手和独立极巨体力。

需要玩家发动的可选本体技能会进入私有选择窗口；对手和观战者只会看到等待状态和最终公开结果。

9 张本体均已迁移为 `worker/src/skills/bodies/` 下的独立技能模块。正面被动、Mega 强化、主动 Z 招式、防御 Z 招式的致伤拦截与 Joker 极巨化都由同一注册架构调度。

## 角色技能与预组解锁

角色技能不从中文效果文本推断规则。`data/cards/character_automation.json` 为 120 张角色登记机器可读的触发时机、次数限制和可用原子操作；技能费用仍读取角色牌 JSON 中的结构化 `cost`。

系统负责验证时机、明置发动者、支付休整或退场费用、处理休整摸牌、记录次数并写入公开日志。已解锁预组使用稳定 ID 的独立角色模块，多步选择保存为 `SkillContinuation`，断线后可从同一步骤继续。

新建自动房可选择全部 9 套已解锁预组，或使用共享自选编辑器，从 9 张已开放本体和全部 120 张角色中选择 16 张不重复角色。Joker 已配套连携组与自动本体模块；KGY 的骑士卡引擎已经实现，但在巡界预组完成前仍不进入玩家选项；南山五与花生壳尚未实现。服务端对创建、加入、换组和准备均校验，不能绕过前端限制。经典模式不受影响。完整进度见 [`auto-battle-character-status.md`](auto-battle-character-status.md)。修改角色时机或费用后运行：

```bash
npm run automation:sync
npm run validate
```

辅助结算层保留用于旧房间兼容。自动模式的自选草稿和当前牌组分别保存为 `qunyou-auto-custom-deck-v1` 与 `qunyou-auto-loadout-v1`，不覆盖经典模式草稿；首次打开编辑器可复用符合自动模式限制的经典草稿。非法或过期草稿回退到已解锁预组。

## 接口与部署

- 经典房：`/rooms/**`，页面 `/play/room`。
- 自动房：`/auto/rooms/**`，页面 `/play/auto/room`。
- 大厅摘要以 `mode: "classic" | "auto"` 区分模式；旧摘要缺少该字段时按经典房处理。
- 自动房由 `AutoBattleRoom` 保存，Cloudflare 迁移版本为 `v3`。

## 状态同步与性能诊断

- Worker 是唯一权威状态：客户端只提交操作意图，操作成功持久化后才发送确认和新快照。
- 对局继续使用按观看者脱敏的完整快照，不依赖客户端增量状态推测，以保证断线重连和隐藏信息一致。
- 普通出牌、响应、技能和阶段操作只保存房间；只有开局、玩家连接变化、观战人数变化和房间结束才同步大厅摘要。
- 客户端同一时间只发送一项权威操作；超过 300ms 显示处理状态，超过 2 秒提示网络较慢，不自动重发。
- 在自动房页面 URL 添加 `perf=1` 可打开开发诊断面板，查看往返、规则处理、持久化、浏览器重绘、快照大小和更新区域。普通玩家默认不显示该面板。

部署时先发布 Worker，再发布前端。完整本地检查：

```bash
npm run validate
npm run typecheck
npm run test:battle
npm run build:battle
npm run test:battle:auto:live
npm run test:battle:e2e
npm run build:web
```
